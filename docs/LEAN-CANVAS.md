## 1. 문제 (Problem)

모임 주최자가 단톡방에서 수작업으로 처리하는 세 가지:

- **참석 인원 집계** — "저요", "저도요", "저는 못 가요"가 대화에 섞여 흘러가고, 주최자가 스크롤을 올려가며 손으로 센다. 뒤늦게 말을 바꾸는 사람이 생기면 처음부터 다시 센다
- **공지 전달** — 장소나 시간이 바뀌면 다시 올려야 하고, 새 대화에 밀려 못 본 사람이 반드시 생긴다
- **회비 정산** — 총액을 인원수로 나누고, 계좌를 다시 올리고, 누가 보냈는지 입금 내역과 대조하고, 안 보낸 사람에게 개별로 다시 말한다. 모임이 끝난 뒤 가장 길게 남는 일

### 기존 대안

- **카카오톡 투표** — 참석 집계까지는 무료로 되지만, 동반 인원·정원·마감이 없고 **정산으로 이어지지 않는다**
- **단톡방 + 손계산 + 메모장** — 가장 흔한 방식
- **네이버 폼·구글 폼** — 응답은 모이지만 주최자가 스프레드시트를 따로 열어야 하고 참여자에게 현황이 보이지 않는다

## 2. 고객 세그먼트 (Customer Segments)

- **핵심 사용자**: 수영·헬스·친구 모임을 **정기적으로** 주최하며 참석 인원과 회비를 직접 관리하는 사람
- **부가 사용자**: 그 모임의 참여자. 응답하고 본인 정산 몫만 확인하면 되므로 요구 수준이 낮다

### 얼리어답터

- 같은 멤버로 **월 1회 이상 반복**되는 모임의 주최자 — 반복 빈도가 높을수록 수작업 피로가 크고, 이벤트 복제의 이점이 즉시 체감된다
- 회비를 **선입금이 아니라 사후 정산**하는 모임 — 정산 고통이 가장 큰 집단
- 참여자가 **8명 이상**인 모임 — 그 아래는 머릿속 계산으로 충분해 도구가 필요 없다

## 3. 가치 제안 (Unique Value Proposition)

> **참석 집계부터 정산까지, 링크 하나로 끝낸다.**

카카오톡을 대체하지 않는다. 카톡에서 하던 일을 링크 하나로 옮긴다. 참석자 데이터가 이미 쌓여 있으므로 **정산은 총액만 입력하면 끝난다.**

### 상위 개념 (High-Level Concept)

**모임용 초대장 + 정산 장부.**

## 4. 해결책 (Solution)

문제 순서에 대응하는 기능입니다. 대괄호는 PRD 기능 ID입니다.

- **참석 집계 → 초대 링크와 RSVP** `F001` `F002` `F003` `F004`
  - 링크 하나로 참석/불참/미정, 동반 인원, 한마디를 받고 상태별로 자동 집계. 동반 포함 총원과 정원 대비 현황을 주최자와 참여자 모두 본다
- **공지 전달 → 누적 공지와 카톡 공유 문구** `F005` `F006`
  - 공지는 초대 페이지 상단에 쌓여 나중에 들어온 사람도 전부 본다. 현재 현황과 링크가 들어간 단톡방용 문구를 자동 생성해 복사한다
- **회비 정산 → N빵 계산과 입금 추적** `F007` `F008` `F009`
  - 총액만 입력하면 참석자 기준으로 자동 분배(불참자 제외)하고, 계좌를 복사해 붙여넣고, 입금 여부를 체크하면 미입금 인원과 금액이 실시간으로 남는다. 참여자는 본인 몫을 직접 확인해 주최자에게 되묻지 않는다
- **반복 사용 → 이벤트 복제와 상태 관리** `F011` `F013`
  - 지난 모임을 복제해 다음 모임을 만든다. 정기 모임일수록 생성 비용이 0에 수렴한다

## 5. 경쟁우위 (Unfair Advantage)

**현재 시점에 진짜 unfair advantage는 없습니다.** 위 기능은 전부 복제 가능하고, 자본이나 특허, 네트워크 효과, 독점 데이터 어느 것도 없습니다. 이 칸을 억지로 채우면 캔버스의 의미가 없어지므로 사실대로 적습니다.

### 축적 가능한 후보

- **주최자 계정에 쌓이는 이력** — 반복 모임의 참여자 구성과 정산 기록이 누적될수록 이전 모임 복제와 재정산이 쉬워지고 이탈 비용이 생긴다. 사용 기간에 비례해서만 자란다
- **주최자 본인이 실사용자** — 개발자가 실제로 모임을 주최하며 만들기 때문에, 설문으로는 안 나오는 실사용 마찰을 직접 겪고 즉시 반영한다
- **카톡을 대체하지 않는다는 포지션** — 정면 승부를 피하고 카톡이 하지 않는 정산에 붙는 선택. 전략적 판단이라 방어막은 아니다

## 6. 수익 흐름 (Revenue Stream)

**MVP 단계에서는 수익 모델이 없습니다.** 무료로 제공하고 가설 검증에만 집중합니다. 결제·송금 연동도 명시적으로 제외한 상태입니다.

### 검증 이후 후보

- **주최자 대상 구독** — 참여자는 계속 무료. 과금 지점을 주최자로 두는 이유는, 참여자에게 돈을 받으면 링크 유통 자체가 멈추기 때문
- **무료/유료 경계 후보** — 월 생성 이벤트 수, 정산 기능, 참여자 인원 상한
- **판단 기준** — 주최자 재사용률이 목표치를 넘기 전까지는 과금 논의를 시작하지 않는다. 재사용하지 않는 제품에 가격을 붙이면 실패 원인을 알 수 없게 된다

## 7. 비용 구조 (Cost Structure)

### 고정비 (월)

- **Supabase** — 무료 플랜으로 시작. 단 **1주일 미사용 시 프로젝트가 일시정지**되므로, 검증 기간에는 유료 전환이나 keep-alive 중 하나를 반드시 결정해야 한다. 정지된 DB는 첫인상을 잃고 지표까지 오염시킨다
- **Vercel** — Hobby 플랜 무료. 상업적 사용이 시작되면 Pro 필요
- **도메인** — 연 1~2만원 수준
- **카카오 개발자 콘솔·구글 OAuth** — 무료

### 초기 일회성 비용

- **개발 시간** — 약 7.5일 (설계 완료 기준)
- **카카오 로그인 연동** — 콘솔 설정 20-30분 + **비즈 앱 전환**. 전환은 선택이 아니라 필수다. Supabase가 `account_email`을 하드코딩해 요청하는데 카카오는 미설정 동의항목을 KOE205로 거부하므로, 이메일을 안 받는 선택지가 존재하지 않는다 (`MVP-PLAN.md` §7). 전환 완료

### 변동비

- MVP 규모에서는 사실상 없음. 알림톡·이메일 발송을 제외했기 때문에 **발송 단가가 발생하지 않는다.** 이것이 카톡 공유 문구 방식을 택한 부수 효과

## 8. 주요 지표 (Key Metrics)

- **주최자 재사용률 — 목표 40%** (첫 이벤트 후 14일 내 두 번째 이벤트 생성) → **주 지표.** 이 하나가 제품 생존 여부를 말한다
- **재방문 참여자 응답률 — 목표 75%** (이미 로그인된 사용자). 마찰이 0인 구간이므로, 여기가 낮으면 로그인 장벽이 아니라 제품 가치 자체가 문제다
- **신규 참여자 전환율 — 목표 35%** (열람 → 로그인 → 응답). 로그인 필수 결정의 실제 비용을 직접 측정한다. **20% 미만이면 그 결정을 재검토한다**
- **정산 완료율 — 목표 70%** (정산 생성 → 전원 입금 체크). 차별 기능이 끝까지 쓰이는지 확인
- **이벤트 생성 소요 시간 — 목표 60초**

### 판정 조건

이벤트 10건, 봇 제외 열람 100건이 쌓이기 전에는 판단하지 않습니다. 모임 빈도상 최소 한 달이 걸립니다.

## 9. 채널 (Channels)

- **카카오톡 단톡방 링크 공유** — 유일한 도달 경로이자 자연스러운 바이럴 루프. 주최자가 링크를 붙여넣으면 참여자 전원이 제품에 노출되고, 그중 일부가 다음 모임의 주최자가 된다
- **본인이 주최하는 실제 모임에 직접 투입** — 초기 사용자 확보 수단. 지인 모임부터 시작해 개인정보 대응 부담도 함께 낮춘다
- **참여자 → 주최자 전환** — 응답 경험이 좋았던 참여자가 자기 모임을 만들 때 재방문. 대시보드의 참여 탭이 그 접점
- **검색·광고는 사용하지 않는다** — 검증 단계에서 유입 비용을 쓰면 제품 가치와 광고 효과를 구분할 수 없다

## 검증 상태

린 캔버스는 사실이 아니라 가설의 집합입니다. 현재 각 칸의 근거 수준을 구분해 둡니다.

- **근거 있음** — 1번 문제, 4번 해결책 (PRD에서 기능 단위까지 확정)
- **미검증 가설** — 2번 고객 세그먼트(얼리어답터 정의), 3번 가치 제안, 8번 주요 지표의 목표치. 실사용 데이터로 확인해야 한다
- **의도적으로 비워 둔 칸** — 5번 경쟁우위, 6번 수익 흐름. 지금 채울 수 있는 내용이 없다는 것이 현재의 정직한 상태이며, 재사용률 검증 이후 다시 채운다

가장 먼저 무너질 수 있는 가정은 **3번 가치 제안**입니다. "정산이 참석 집계보다 아프다"가 틀리면 카카오톡 투표 대비 우위가 사라지고, 나머지 칸이 전부 무의미해집니다. 8번의 정산 완료율이 이 가정을 직접 검증합니다.
